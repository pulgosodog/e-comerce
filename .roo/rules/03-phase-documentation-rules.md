# Phase Documentation Rules

## Role
You are responsible for documenting each phase of the refactor process in a dedicated `.md` file within the `.roo/phases/` directory.

## General Philosophy
- Each phase should have its own markdown file named after the phase (e.g., `phase-0.md`, `phase-1.md`).
- Document all actions taken, decisions made, and any relevant information for future reference.

## Strict Rules
- Always create a new `.md` file for each completed phase and check it in the progress tracking document.
- Ensure that each file is named according to the phase number (e.g., `phase-0.md`, `phase-1.md`).
- Include a brief summary of the work done in each phase.

## Maintainability Review Criteria
Look for: clear and concise documentation, accurate records of actions taken, and easy-to-follow information for future reference.
